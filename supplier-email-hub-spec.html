Supplier Email Hub

Feature Specification  ·  Travel Collection CRM  ·  Bookings Module  ·  April 2026

1. Overview

The Supplier Email Hub is a modal component integrated into the Trip Bookings List. It gives the Operations team a single interface to read, compose, and send emails to all suppliers on a trip — covering initial booking requests, modifications, cancellations, and follow-up reminders.

1.1 Problems it solves

  • Sending booking emails to multiple suppliers is slow and error-prone when done one by one.
  • There is no consolidated view of which suppliers have been contacted, confirmed, and which still need a reminder.
  • Ops has no structured way to flag a booking for a follow-up reminder after sending an email.
  • Email history per supplier is scattered — Ops cannot see the full thread when composing a reply.

1.2 Entry point

A Send emails button is added to the Bookings List toolbar (alongside "Import Bookings" and "Save"). Clicking it opens the Supplier Email Hub modal with a mode selector:

ModePurposeHighlights suppliers with…
Booking emailsHold requests, confirmations, modificationsAt least one booking in Draft or On Hold
RemindersFollow-up remindersAt least one booking with reminder status None or Needed

A ← Change mode link in the modal footer lets the user switch without closing.

2. Modal Layout

The modal is a full-screen 3-panel layout:

PanelWidthAlways visiblePurpose
Left~230pxYesSupplier list with filters
MiddleFlexYesThread list or compose area
Right~260pxYesBookings + Parameters tabs (appear after a template is chosen)

3. Left Panel — Supplier List

3.1 Filter bar

FilterShows suppliers where…
All (default)All suppliers on the trip
Booking neededAt least one booking has status Draft or On Hold
Reminder neededAt least one booking has reminder status None or Needed

Suppliers excluded by the active filter are dimmed rather than hidden.

3.2 Supplier rows

Each row shows:

  • Supplier name, date range, booking count
  • Booking status breakdown — badge per distinct status across all bookings (e.g. "2 On Hold · 2 Draft")
  • Reminder status breakdown — clock icon + label per distinct reminder status (e.g. "2 Needed · 1 Sent")

Clicking a row loads that supplier in the Middle panel. Only one supplier is active at a time — no multi-select.

3.3 Footer badge

Shows X / N suppliers confirmed where confirmed = all bookings for that supplier are in Requested or Booked status.

4. Middle Panel — Thread List & Compose

4.1 Thread list (step 1)

When a supplier is selected, the middle panel shows:

  • Supplier name and email in the panel header
  • List of existing email threads (subject, last message preview, date)
  • A "New thread" option at the bottom

4.2 Compose area (step 2)

FieldBehaviour
FromRead-only. Current user's email.
ToPre-filled from supplier record. Editable.
SubjectExisting thread: locked to Re: [thread subject]. New thread: open input.
TemplateDropdown. Changing it regenerates the email body and right panel parameters.
Email bodyAuto-generated from template + selected bookings + parameter values. Editable.

4.3 Previous emails (existing thread only)

Thread history shown below the email body, newest-first. Most recent email expanded by default; older ones collapsed. Each email shows direction (Sent / Received), sender, date, preview, and full body on expand. Green left border = sent, amber = received.

5. Right Panel — Options

Shows "Select a template to see options" until a template is chosen. Two tabs then appear.

5.1 Bookings tab

Lists all bookings for the selected supplier. Each row shows:

  • Checkbox to include/exclude from the email
  • Service name and dates
  • Booking status badge
  • Reminder status chip (clock icon + label)

Tab badge shows selected / total (e.g. "2/4"). Toggling a booking immediately regenerates the email body.

5.2 Parameters tab (default)

Shows template-specific parameters. Three types are supported:

TypeUI controlExample
BooleanCheckboxCC Finance team
TextFree text inputSpecial instructions
DropdownSelectLanguage: English / French / Spanish

Changing any parameter immediately regenerates the email body. This tab is the default active tab when a template is chosen.

CC Finance team and CC Operations team are parameters on each template (not hardcoded fields), with their own defaults per template.

6. Compose Footer

6.1 Status summary

Once a template is chosen, a summary bar appears above the action buttons showing which fields will be updated on send and their before → after values. Only fields that actually change are shown.

  • Booking status — breakdown of current statuses across selected bookings → new status they will all move to
  • Reminder status — current reminder breakdown → new value

6.2 Reminder needed toggle

Appears for all template families except Reminder. Checked by default when a template is chosen.

  • Checked → reminder status of all selected bookings will be set to Needed
  • Unchecked → reminder status of all selected bookings will be set to Not needed

6.3 Send button

Disabled until a template is chosen. On click:

  1. The email is sent to the supplier.
  2. Status changes are applied automatically to all selected bookings (see Section 7).
  3. A confirmation screen shows: supplier name, template used, and the exact field changes (before → after badges). Clicking Done returns to the thread list.

11. Out of Scope (v1)

  • Automatic reminder scheduling or date-based reminder triggers
  • Tracking email replies automatically — confirmation is set manually by Ops
  • Bulk "send all" — Ops composes and sends one supplier at a time
  • Creating or editing email templates from within the hub
  • Sending to multiple contacts at the same supplier simultaneously
